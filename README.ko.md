# bmo-cli

플랫폼의 얇은 진입점인 `bmo`입니다. API를 갖지 않으며 서비스도 실행하지 않습니다. 각 유닛은 `bmo-<unit>`이라는
이름의 자체 명령을 함께 배포하고, `bmo`는 git이 `git-<command>`를 찾는 방식처럼 해당 명령을 가진 유닛 명령을 찾아
명령을 넘겨줍니다. 나중에 추가되는 유닛이 있어도 `bmo`를 다시 빌드할 필요가 없습니다.

## 구성

| 폴더 | 내용 |
|---|---|
| `src/` | 입력된 단어를 읽고, 유닛 명령과 그 명사를 찾고, 명령을 해석해 넘겨주는 라이브러리와 `bmo` 바이너리 |
| `tests/` | 계약 테스트. 각 테스트는 빌드된 `bmo`를 자체 디렉터리 안의 대역 유닛 명령에 대해 실행합니다 |
| `docs/` | `bmo`가 하는 일에 대한 정본 문서와 개인 정보 규칙 |

루트에는 Cargo 매니페스트, 버전, `testbed.toml`(이 저장소를 어떻게 테스트·검사·빌드·배포하는지 적은 bmo-testbed의
선언), 테스트베드의 `korean` 검사가 읽는 한국어 대장, `rustfmt.toml`, `CLAUDE.md`, 그리고 `LICENSE`의 MIT 라이선스가
있습니다.

## 문서

| 문서 | 내용 |
|---|---|
| `docs/api.md` | 고정 API: 유닛 명령을 찾고 그 명사를 선언하는 방법, 명령을 해석해 넘겨주는 방법, `bmo`가 직접 답하는 것, 그리고 홈 브리지 |
| `docs/boundary.md` | 경계의 위치: 이 저장소의 경계 문서를 가리키는 유닛을 위해 `docs/api.md`의 고정 API로 안내합니다 |
| `docs/inventory.md` | 이 저장소가 분리되어 나온 단일 저장소에서 가져온 것과 유닛에 맡기는 것 |
| `docs/PERSONAL-DATA.md` | 이 저장소에 절대 넣지 않는 개인 정보, 대신 써야 할 것, 그리고 추적되는 모든 파일을 읽어 이를 확인하는 테스트베드의 검사 |
