# bmo-cli

プラットフォームの薄い入口である `bmo` です。API は持たず、サービスも動かしません。各ユニットは `bmo-<unit>` という名前の
独自コマンドを同梱し、`bmo` は git が `git-<command>` を見つけるのと同じように、そのコマンドを持つユニットのコマンドを
見つけてコマンドを引き渡します。後から追加されたユニットのために `bmo` をビルドし直す必要はありません。

## 構成

| フォルダ | 内容 |
|---|---|
| `src/` | 入力された語を読み取り、ユニットのコマンドとその名詞を見つけ、コマンドを解決して引き渡すライブラリと、バイナリ `bmo` |
| `tests/` | 契約のテスト。それぞれ専用のディレクトリで、ビルド済みの `bmo` を代役のユニットコマンドに対して実行します |
| `docs/` | `bmo` の動作についての正典となる文書と、個人情報のルール |

ルートには Cargo マニフェスト、バージョン、`testbed.toml`(このリポジトリのテスト・チェック・ビルド・デプロイ方法を記した
bmo-testbed の宣言)、`install.toml`(新しいマシンへのインストールに必要なものを記した、テストベッドの install 動詞が読む宣言)、テストベッドの `korean` チェックが読む韓国語台帳、`rustfmt.toml`、`CLAUDE.md`、そして `LICENSE` の
MIT ライセンスが置かれています。

## ドキュメント

| ドキュメント | 内容 |
|---|---|
| `docs/api.md` | 固定 API:ユニットのコマンドの見つけ方と名詞の宣言方法、コマンドの解決と引き渡し、`bmo` 自身が答えるもの、そしてホームブリッジ |
| `docs/boundary.md` | 境界の所在:このリポジトリの境界ドキュメントを参照するユニットのために、`docs/api.md` の固定 API を案内します |
| `docs/inventory.md` | このリポジトリが分割元の単一リポジトリから引き継いだものと、ユニットに任せるもの |
| `docs/PERSONAL-DATA.md` | このリポジトリに決して入れない個人情報、代わりに書くもの、そして追跡されている全ファイルを読んでそれを確かめるテストベッドのチェック |
